Case Study

Running a Twelve-Part Project with AI as a Working Partner

The Problem

A tabletop RPG sounds like one thing. It isn't. It's a lot of different deliverables that all have to agree with each other.

20 Below grew into a rulebook manuscript that feeds a web book, a reference document, and a print PDF. It has four apps, each shipped as both a web build and a desktop build: a character creator, a battle tracker, an encounter calculator, and a page-layout tool. There are three extensions for a virtual tabletop, each in its own repository. There's a campaign setting in its own repository too, and a brand library of reference sheets, diagrams and dividers. Change one rule and it can land in eight places. If you miss one, a player finds it at the table.

I was doing all of it alone, with an AI assistant as the only other set of hands.

Analysis

With a team, the risk is people not talking to each other. Working solo with an AI, the risk is quieter: you trust output because it sounds sure of itself. An AI assistant is fast, tireless, and confidently wrong often enough that "it said it's done" can't be the same thing as "it's done."

So the real job wasn't writing prompts. It was the same job a producer has on set: know what the finished thing is supposed to be, break it into pieces someone else can execute, and check every piece against the source before it ships. The AI changed who executes. It didn't change who's accountable.

Design Decisions

  • One source of truth, many outputs. The Scrivener manuscript is canonical. The web book, the print PDF, and the layout tool's input are all generated from it by script, not maintained by hand. When they drift, it gets fixed at the source and then run through a "rules-sync" pass, not patched in whichever copy someone noticed.
  • Change control before every edit pass. Every rewrite of a print chapter started with a named snapshot: before-rules-sync, before-literacy-cut, before-element-rebalance. That's fifty-two of them in the two weeks leading up to the print build. Any pass that went wrong could be put back exactly as it was before that pass, not approximately, and the name says what the pass was for.
  • Small, scoped, versioned releases. Every change is its own commit with a plain-language reason, and the apps ship as tagged versions, 113 so far. If something breaks, I can name the release it broke in.
  • Verify the collaborator. The AI told me, more than once, that pieces of the brand library didn't exist. I'd already built them, and I pointed it to the files. It also caught me: the download page claimed one of the extensions could read a character file, and when it checked that claim against the extension's own code, the claim was false. Both directions matter. Neither of us gets to be the source of truth. The code is.
  • Run work in parallel, keep it out of each other's way. While this portfolio was being built in one session, a second AI session was researching and building a Roll20 integration in the same repository. Commits were staged file by file, never as whole folders, so neither stream of work could sweep up the other's half-finished changes.
  • Keep the known problems visible. There's an unresolved formatting mismatch between the web and print versions of the Gift list. It's written into the project's own architecture diagram instead of left for someone to rediscover. A risk log that only lists the solved risks isn't doing its job.

Outcome

A system with a lot of moving parts ships as one thing and holds together: one set of rules behind every app, and a print book and web book built from the same source. It was done at a pace one person couldn't have managed alone, and without the drift that usually comes with that pace. The AI did a large share of the typing. The scope, the sequencing, the change control, and the final call on whether something was actually right stayed with me. That split is the skill I'd bring to a team.

What this isn't. This is a solo project. There was no team to lead, no budget to defend, and no stakeholders pulling in different directions. It shows scope, sequencing, change control, quality control, and how to delegate to an AI and check its work. It doesn't show managing people.
